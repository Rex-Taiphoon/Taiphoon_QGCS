# ADR-0019：多機影像串流與獨立視窗

**日期**：2026-10-29
**狀態**：已接受
**相關**：ADR-0009（介面配置）、ADR-0013（Qt 原生桌面程式）、ADR-0017（iOS 交叉編譯）、ADR-0018（語音口令使用 Qt Multimedia）

## 背景

開發者要求地面站能播放無人機的影像串流：多機同時顯示，且每一台都能在獨立視窗播放。

`Taiphoon_Agent_Interfaces` 目前沒有任何影像 topic 或串流規格，Taiphoon_Agent 的影像串流仍在規劃中。
影像資料量大，也不適合走 DDS（介面文件的 QoS 與頻寬規劃都未涵蓋）；常見做法是機上以 RTSP 等串流伺服器提供，
地面站直接連線播放。

已定案（2026-10-29 開發者選擇）：

- 串流位置以 **URL 範本**設定，RTSP 為主；
- 多機畫面放在**右下角浮動縮圖面板**，地圖維持全幅；
- 這一輪支援桌面三平台（Windows、macOS、Linux）。

## 決策

### 串流位置（VideoController）

- 不變更 Agent 介面。地面站設定一個含 `{N}`（UAV 編號）或 `{agent}`（`uav_N_agent`）的**機群網址**範本，
  套用到 DDS 發現的每一台無人機；個別機不同時設定**單機網址**，優先於機群網址。
- 單機網址清空，或與機群網址代入結果相同時，不另存單機網址：日後修改機群網址時，這台會一起更新。
- 範本**必須**含 `{N}` 或 `{agent}`：沒有編號的範本會讓每一格顯示同一路影像，操作人員可能把畫面誤認成別台。
- 只接受即時串流協定：`rtsp`、`rtsps`、`rtmp`、`rtmps`、`srt`、`udp`、`rtp`、`tcp`、`http`、`https`；
  不接受 `file` 等本機來源，避免把錄影檔當成即時畫面。
- URL 屬站點設定（`site/video/...`），面板展開狀態屬介面設定（`ui/video_panel_open`）。
  URL 可含帳號密碼，日誌一律移除帳號密碼後再記錄；設定檔本身以明文保存，與其他站點設定相同。
- `VideoController` 只依賴 QtCore，放在 `gcs_ui`，可在無畫面環境單元測試。

### 播放（VideoPlayer）

- 使用 Qt Multimedia 的 FFmpeg 後端（`QMediaPlayer`），`QPlaybackOptions` 設為 `LowLatencyStreaming`，
  網路逾時 5 秒；不輸出聲音。不新增第三方相依：Qt Multimedia 已因語音口令隨安裝檔部署（ADR-0018）。
- **每台無人機只有一個播放器、一路連線**。播放器的畫面先送到內部 `QVideoSink`，再轉送到縮圖與獨立視窗的
  `VideoOutput`；機上串流伺服器的連線數與無線鏈路頻寬都有限，不能因為多開一個視窗就多拉一路。
- 面板展開或該機的獨立視窗開啟時才播放；兩者都關閉時停止並釋放連線。
- 連線失敗、串流結束、開始 10 秒內沒有第一張畫面，或播放中 5 秒沒有新畫面，視為中斷：
  **清除畫面**並顯示「影像中斷，重新連線中…」，3 秒後重新連線。凍結的最後一張畫面容易被誤認為即時影像，因此不保留。
- `VideoPlayer` 放在獨立的 `gcs_video_playback` 靜態函式庫（與 `gcs_voice_capture` 相同理由：執行檔目標的
  autogen 不會處理後來加入的 QObject 標頭），由 `main.cpp` 以 `qmlRegisterType` 註冊為 `TaiphoonQgcs.Video 1.0`。

### 介面

- `VideoPanel.qml`：右下角、地圖縮放按鈕左側的浮動面板，與機群面板相同可最小化；
  每台線上無人機一格 16:9 縮圖，依可用寬度排列，超出高度時捲動。機群清單取自 `UiBridge.fleetModel`，不寫死數量。
- `VideoTile.qml`：點選選取該機（與機群表格相同）；雙擊或按右上角按鈕開啟獨立視窗。播放器屬於縮圖，
  無人機從機隊消失（離線）時縮圖、播放器與獨立視窗一併關閉。
- `VideoWindow.qml`：不設定 `transientParent`，可移到其他螢幕、被主視窗遮住或單獨最小化；雙擊或 F11 全螢幕，
  Esc 離開全螢幕。因為不隸屬主視窗，主視窗關閉時明確結束程式。
- 獨立視窗疊加**該機的完整狀態**（開發者要求，2026-10-29），不限於目前選取機：上方為機號、任務階段、
  PX4 飛行模式、PX4 解鎖／落地狀態、電量／電壓／電流與解析度；下方為高度、NED、經緯度、航向、Roll、Pitch，
  左下角姿態儀。版面沿用主畫面狀態列的儀表格，視窗變窄時換行而不截斷數值；等待飛控時只顯示機號與「等待飛控連線中...」。
  資料直接取自 `fleetModel` 該機的列（縮圖把整列 `model` 交給視窗），為此 `FleetModel` 新增
  `px4StatusLabel`、`nedText`、`positionText` 三個角色；經緯度與地圖相同，套用「地圖顯示位置」換算。
- 縮圖與獨立視窗屬於 `fleetModel` 的 delegate，因此 `FleetModel` 改為**增量更新**：只有新上線或離線的列
  插入／移除，其他列保留。原本機隊成員一變動就整體重設，會讓所有縮圖重新連線、已開的獨立視窗被關閉。
  這也影響機群表與地圖標記的 delegate（不再全部重建），顯示內容不變。
- 串流網址在**機群表的右鍵選單**設定（開發者要求，2026-10-29）：在「全部」按右鍵編輯機群網址，
  在單機列按右鍵編輯該機網址；右鍵不改變選取。`VideoSourceDialog.qml` 開啟時顯示目前網址
  （機群網址另列出每台線上無人機實際使用的網址與是否為單機網址），**關閉時自動套用**，沒有另外的套用按鈕。
  內容不合法時重新開啟並保留輸入與錯誤原因，修正或按「還原」後才能關閉，避免悄悄丟掉修改；未變更時不通知，
  各格不會無故重新連線。驗證與套用規則在 `VideoController`（C++），QML 只負責呈現。
- 最初放在進階設定的「影像串流」區（範本加多行單機設定文字）已移除：設定位置要貼近機群，且多行文字格式容易寫錯。
- 影像相關 QML 檔只在有 Qt Multimedia 的平台加入 QML 模組，`Main.qml` 以 `Loader` 載入；
  其他平台（iOS）不顯示影像面板，機群表也不提供右鍵設定。

## 替代方案

| 方案 | 否決原因 |
|------|----------|
| 經 DDS 傳送影像（例如 `sensor_msgs/Image`） | 需變更 Agent 介面；未壓縮影像超出無線鏈路頻寬，介面文件也沒有對應 QoS |
| QGC 式 UDP RTP（每機一個埠，需 SDP） | 要為每台準備 SDP 與防火牆規則；仍可用 `udp://` 單機網址接收 MPEG-TS |
| 每個視窗各自建立播放器 | 同一台會開兩路連線，機上伺服器與鏈路頻寬加倍 |
| 引入 GStreamer | 新增大型第三方相依與三平台打包負擔；Qt Multimedia 的 FFmpeg 後端已足夠 |
| 狀態列切換全幅影像牆、地圖與影像左右分割 | 開發者選擇保留全幅地圖、右下浮動縮圖 |

## 後果

- 機上需要另外提供串流伺服器（例如 MediaMTX），且串流位置要與 DDS namespace 的編號對應；
  Agent 若日後在介面中公告影像位址，可改為自動取得，屆時需更新本 ADR。
- 延遲取決於來源的編碼設定與 FFmpeg 緩衝；即時操作仍以遙測與地圖為準，影像僅供觀察。
- iOS 版這一輪沒有影像功能；要支援需在 iOS 建置加入 Qt Multimedia，並處理獨立視窗無法使用的問題。
- 以 MediaMTX 產生 4 路 H.264 RTSP 測試串流，搭配 Docker Desktop 4 機 SITL 驗證縮圖、獨立視窗與重新連線；
  真實機載攝影機與無線鏈路的延遲、丟包表現仍需實地測試。
